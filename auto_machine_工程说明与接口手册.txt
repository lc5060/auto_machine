 一、工程概览
================================================================================

--------------------------------------------------------------------------------
 1.1 功能定位
--------------------------------------------------------------------------------

 本包把五类工业设备的 RS485/Modbus-RTU 协议封装成一个统一的 ROS2 服务，
 上层（UI / PLC / 机器人 / 其它节点）只需要关注三个字段：

     dev_type    什么设备（T1 / V6 / MAG04 / MAG06 / XYZR）
     command     什么动作（每个设备一套命令号）
     param_data  参数（多数情况只有第 0 字节 = 串口索引）

 并拿到三个字段：

     success     是否成功
     err_code    错误码（0 = 成功）
     ret_data    返回数据（状态值，大端 2 字节）

 节点同时负责：
   · 闭环控制——下发动作后自动轮询状态寄存器，直到到位或超时
   · 故障主动上报——后台周期轮询，状态变化时通过话题推送
   · 多串口并发——每个串口独立线程处理，互不阻塞

--------------------------------------------------------------------------------
 1.3 设备与从站地址
--------------------------------------------------------------------------------

  设备           dev_type        十进制        从站地址   说明
  ------------   -------------   -----------   ---------  ----------------------
  T1             0x00000001      1             0x01       模板机/缝制单元
  V6             0x00000002      2             0x01       折叠机
  MAG04          0x00000003      3             0x01       钉扣机（老款）
  MAG06          0x00000004      4             0x01       钉扣机（M6）
  XYZR           0x10000001      268435457     0x02       对齐/移料装置
  （A100）       0x00000005      5             ——         未实现，调用返回 10004

  重要：T1 / V6 / MAG04 / MAG06 的从站地址**都是 0x01**，
        因此一条总线上只能挂其中一台；XYZR 是 0x02，可与任一台共存。


--------------------------------------------------------------------------------
 1.4 总线拓扑规则
--------------------------------------------------------------------------------

  允许的组合（一条 RS485 总线）：
      自动机(0x01) + XYZR(0x02)          ← 推荐，本工程实测通过
      仅自动机(0x01)
      仅 XYZR(0x02)

  不允许的组合：
      两台 0x01 设备同总线（地址冲突，会同时应答导致帧错乱）

  一条总线 = 节点里的一个串口索引 = mag_serial_ports 里的一个元素。
  同一个索引下，自动机与 XYZR 共用同一个 ModbusRtu 实例（同一把总线锁），
  靠从站地址区分，互不串线。

 二、安装与串口准备

 2.1 编译
--------------------------------------------------------------------------------

 把 auto_machine 包放到工作区 src/ 下，然后：

   cd ~/your_ws
   source /opt/ros/jazzy/setup.bash
   colcon build --packages-select auto_machine
   source install/setup.bash

 说明：
   · 改了 msg/srv 必须重新 build，否则接口不生效
   · 每个新终端都要重新 source install/setup.bash
   · 若报 CMakeCache 路径不一致，删掉该包的 build/install 目录后重编：
       rm -rf build/auto_machine install/auto_machine


--------------------------------------------------------------------------------
 2.2 udev 固定软链接（/dev/ttyRS485）
--------------------------------------------------------------------------------

 【为什么需要】
   USB 转 485 的 ttyUSB 编号会随插拔顺序变化（今天 ttyUSB0，明天可能 ttyUSB3）。
   用 udev 规则按 USB 物理端口生成固定名字，换口、重启都不会变。

 【生成哪些名字】
   /dev/ttyRS485            单机通用名（所有 CP210x 都会生成，向后兼容）
   /dev/ttyRS485_0          多机 0 号（按 USB 物理端口 KERNELS 匹配）
   /dev/ttyRS485_1          多机 1 号（可换不同芯片，如 FTDI 0403:6015）

 【先查每台设备的物理端口】

   插上第一个 USB-485，执行：
     udevadm info -a -n /dev/ttyUSB0 | grep -E "KERNELS|idVendor|idProduct"

   记下形如 3-1.1 的端口路径（不含末尾 :1.0 接口号）。
   换到另一个 USB 口再插一次，重复上面命令，得到第二个路径。

 【改规则】
   编辑 udev/99-usb-rs485.rules，把 KERNELS 改成上面查到的值；
   换芯片时同时改 idVendor / idProduct。

 【安装（只需一次，需 root）】

   cd auto_machine            # 仓库根目录
   sudo bash install_rs485_udev.sh

   等价于手动执行：
     sudo cp udev/99-usb-rs485.rules /etc/udev/rules.d/
     sudo udevadm control --reload-rules
     sudo udevadm trigger

 【验证】

   ls -l /dev/ttyRS485*
   # 应看到指向 ttyUSBx 的软链接；没插设备时不出现是正常的

   权限说明：规则里 MODE="0666"，普通用户可直接读写，无需 sudo 运行节点。


 三、启动节点
================================================================================

--------------------------------------------------------------------------------
 3.1 单串口（最简）
--------------------------------------------------------------------------------

   ros2 run auto_machine auto_machine_node --ros-args -p serial_port:=/dev/ttyRS485

   · serial_port 默认值就是 /dev/ttyRS485，装了 udev 规则时可以不传
   · 此模式下设备索引只接受 0

 启动成功会打印：

   串口已打开: /dev/ttyRS485 (115200 8O1 RTU)
   auto_machine_node 启动，服务: auto_machine/command, 主题: auto_machine/fault，
   串口数: 1，执行器线程数: 4


--------------------------------------------------------------------------------
 3.2 多串口 / 同口双从站
--------------------------------------------------------------------------------

  两台自动机，各自一条总线，每条总线上挂「自动机 0x01 + XYZR 0x02」：

   ros2 run auto_machine auto_machine_node --ros-args \
     -p "mag_serial_ports:=['/dev/ttyRS485_0','/dev/ttyRS485_1']"

   · 数组顺序 = 设备索引：第 0 个是 0 号机，第 1 个是 1 号机
   · 之后所有命令用 param_data[0] 指定索引：[0] 发 0 号机，[1] 发 1 号机
   · 同一索引下自动机与 XYZR 共用同一个串口实例，无需给 XYZR 单独配串口

  只挂一台自动机但想用数组形式也可以：

   ros2 run auto_machine auto_machine_node --ros-args \
     -p "mag_serial_ports:=['/dev/ttyRS485_0']"


--------------------------------------------------------------------------------
 3.3 参数总表
--------------------------------------------------------------------------------

  参数名                      默认值            说明
  --------------------------  ----------------  ------------------------------
  serial_port                 /dev/ttyRS485     单串口模式用
  mag_serial_ports            []（空）          多串口模式用，按索引对应
  auto_query_delay_ms         500               闭环：下发后首次查询前等待
  auto_query_poll_interval_ms 300               闭环：之后每次查询间隔
  auto_query_timeout_ms       30000             闭环：多久未到位判超时
  fault_poll_interval_ms      1000              故障上报轮询周期
  executor_threads            0                 执行器线程数，0=自动
                                                自动值 = max(4, 2 × 串口数)

  调整示例（整件缝纫较慢，把闭环超时放到 60 秒）：

   ros2 run auto_machine auto_machine_node --ros-args \
     -p serial_port:=/dev/ttyRS485 -p auto_query_timeout_ms:=60000

  executor_threads 说明：
   每个「阻塞等结果」的闭环请求会独占一个执行线程，所以 2 个串口默认给 4 个。
   串口很多（≥4）时可手动调大，例如 -p executor_threads:=12。

 四、接口约定
================================================================================

--------------------------------------------------------------------------------
 4.1 服务与话题
--------------------------------------------------------------------------------

 【服务】

   名称：/auto_machine/command
   类型：auto_machine/srv/AutoMachine

   请求：
     uint32  dev_type      设备类型，见 1.3
     uint32  command       命令号，见 5.7 速查表
     uint8[] param_data    参数，通常 [串口索引]

   响应：
     bool    success       true = 成功
     int32   err_code      0 = 成功，其它见 4.5
     uint8[] ret_data      返回数据，多为 2 字节大端（见 4.4）

   命令行模板：

     ros2 service call /auto_machine/command auto_machine/srv/AutoMachine \
       "{dev_type: <类型>, command: <命令号>, param_data: [<索引>]}"

 【话题（故障上报）】

   名称：/auto_machine/fault
   类型：auto_machine/msg/DeviceFault

     std_msgs/Header header
     uint32 dev_type       设备类型
     uint8  device_index   串口索引
     uint16 fault_code     故障码（0 = 无故障，即恢复）
     bool   comm_fault     通讯故障标记

   触发条件：故障码变化（边沿触发），开启监控时先推一条当前状态作为基准。


--------------------------------------------------------------------------------
 4.2 设备索引（param_data[0]）
--------------------------------------------------------------------------------

   param_data[0] = 串口索引，对应 mag_serial_ports 的第几个元素

     [0]  → 0 号机（/dev/ttyRS485_0）
     [1]  → 1 号机（/dev/ttyRS485_1）

   规则：
     · T1 / V6 / XYZR  —— 省略 param_data 时默认 0（兼容单机旧调用）
     · MAG04 / MAG06   —— 必须显式提供索引，否则返回 10003
     · 索引越界（超过串口数量）→ 返回 10003

   注意：XYZR 与自动机共用同一索引。同一串口上的自动机和对齐装置，
         都用同一个 param_data[0]。


--------------------------------------------------------------------------------
 4.3 三类命令（返回语义）
--------------------------------------------------------------------------------

 【闭环控制】〔闭环〕—— 下发后自动轮询状态直到到位

    到位：success=True  err_code=0     ret_data=[高,低]（最终状态值）
    超时：success=False err_code=10008 ret_data=[高,低]（最后一次状态）
    通讯：success=False err_code=10006 ret_data=[]（或最后状态）
    忙  ：success=False err_code=10009 ret_data=提示文字

 【仅下发】〔仅下发〕—— 协议没有反馈位，写进去就返回

    success=True err_code=0 ret_data=[]
    只代表「指令已发出」，不代表设备已经做完。

 【状态查询】〔查询〕—— 立即返回寄存器值

    success=True err_code=0 ret_data=[高,低]

 闭环命令共 21 条，清单见 5.8。


--------------------------------------------------------------------------------
 4.4 ret_data 换算
--------------------------------------------------------------------------------

   协议里状态值都小于 256，所以高字节恒为 0：

     V = ret_data[0] * 256 + ret_data[1]

   例：
     ret_data=[0,0]   → V=0
     ret_data=[0,3]   → V=3
     ret_data=[0,10]  → V=10
     ret_data=[0,100] → V=100

   注意：状态位含义各设备不同，见第五章每条的说明。
         T1 的运行状态是位域（bit0 复位、bit1 缝纫），其它多为枚举值。


--------------------------------------------------------------------------------
 4.5 错误码
--------------------------------------------------------------------------------

   0       成功
   10001   未知设备类型（dev_type 写错）
   10002   未知命令（command 号不存在；删掉的旧命令也返回这个）
   10003   参数错误（MAG 缺 param_data[0]、索引越界、参数长度不符）
   10004   功能未实现（A100 等预留设备）
   10005   内部错误（协议处理抛异常）
   10006   通讯失败（串口打不开 / 设备无应答 / CRC 错 / 地址不符 /
                        设备返回 Modbus 异常帧）
   10007   设备返回异常（当前版本未使用，异常帧也归到 10006）
   10008   动作超时未到位（闭环专用：通讯正常但状态一直没到目标值）
   10009   串口忙：同一串口已有闭环命令在执行，请稍后重试

 10006 与 10008 的区别：
   10006 = 帧都没走通（通讯层失败），ret_data 通常为空
   10008 = 帧走通了、状态也读到了，但没到目标值，ret_data 带最后状态


--------------------------------------------------------------------------------
 4.6 并发行为与 10009
--------------------------------------------------------------------------------

 节点内部用「多线程执行器 + 可重入回调组」，因此：

 1) 不同串口互不阻塞
    串口 0 在等「缝制完成」（可能几十秒）时，串口 1 的命令依然毫秒级返回。

 2) 同一串口的闭环命令互斥（忙则拒，不排队）
    同一串口上已有闭环命令在执行时，再发【闭环】命令会立即返回 10009，
    不等待、不排队。由上层决定是否重试。

 3) 非闭环命令可插入
    查询、急停、吹气等【仅下发】/【查询】命令不占用串口，
    在闭环等待期间仍可正常下发，不会被 10009 挡住。

 对上层的要求：
   如果 UI 在按钮回调里同步调用服务，请改为后台线程发请求，
   否则 UI 自身会被串口 0 的闭环卡住，节点的并发能力发挥不出来。

--------------------------------------------------------------------------------
 5.1 T1（dev_type=1，从站 0x01）
--------------------------------------------------------------------------------

 —— 闭环控制 ——

【T1-1】复位  〔闭环〕 command=65550 (0x0001000E)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65550, param_data: [0]}"
  到位：ret_data=[0,V]，V 为运行状态字，bit0=1 表示回零完成。
        V=1 复位完成；V=3 复位完成且本件缝纫也完成（V 为奇数即可视为已复位）。
  超时：err_code=10008，ret_data 为最后状态（bit0 仍为 0 说明没回零）。

【T1-2】开始工作（等本件缝纫完成）〔闭环〕 command=65545 (0x00010009)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65545, param_data: [0]}"
  到位：ret_data=[0,V]，bit1=1 表示缝纫完成。V=2 缝纫完成；V=3 复位+缝纫都完成。

【T1-3】打开吸风（等确实开启）〔闭环〕 command=65548 (0x0001000C)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65548, param_data: [0]}"
  到位：ret_data=[0,V]，V 非 0（正常为 1）即已开启。

【T1-4】关闭吸风（等确实关闭）〔闭环〕 command=65552 (0x00010010)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65552, param_data: [0]}"
  到位：ret_data=[0,0]。

 —— 仅下发 ——

【T1-5】压框下压  〔仅下发〕 command=65544 (0x00010008)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65544, param_data: [0]}"
  返回：success=True err_code=0 ret_data=[]

【T1-6】压框抬起  〔仅下发〕 command=65551 (0x0001000F)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65551, param_data: [0]}"
  返回：success=True err_code=0 ret_data=[]

【T1-7】暂停工作  〔仅下发〕 command=65546 (0x0001000A)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65546, param_data: [0]}"

【T1-8】自动化下一步  〔仅下发〕 command=65549 (0x0001000D)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65549, param_data: [0]}"

 —— 状态查询 ——

【T1-查1】运行状态  〔查询〕 command=65537 (0x00010001)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65537, param_data: [0]}"
  ret_data=[0,V]：bit0=1 已复位，bit1=1 缝纫完成。
    V=0 都没完成；V=1 已复位；V=2 缝纫完成；V=3 两者都完成。

【T1-查2】故障码  〔查询〕 command=65538 (0x00010002)
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65538, param_data: [0]}"

 5.6 全局命令：故障上报开关
--------------------------------------------------------------------------------

 command = 4026531841 (0xF0000001)，不属于任何具体设备。
 dev_type 字段填【要监控的设备类型】，param_data 有两种写法：

   [enable]                  —— 只给 1 字节，默认监控 0 号机
                               （T1 / V6 / XYZR 可用）
   [enable, device_index]    —— 指定串口索引（MAG04 / MAG06 必须用这种）

 enable：1 = 打开，0 = 关闭。

  打开 0 号 T1 的故障上报：
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 4026531841, param_data: [1, 0]}"

  关闭 0 号 V6：
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 2, command: 4026531841, param_data: [0, 0]}"

  打开 1 号 XYZR：
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 268435457, command: 4026531841, param_data: [1, 1]}"

  返回 success=True err_code=0 ret_data=[] 表示开关设置成功。

 判定规则：
   T1 / V6 / MAG04 / MAG06  —— 故障码非 0 即为故障
   XYZR                     —— 主控状态 = 100 才算故障

================================================================================
 六、测试
================================================================================

 虚拟测试与实机测试的区别只有一个：虚拟测试要先起假从站，把 /dev/pts/N 当串口用；
 实机测试直接用 /dev/ttyRS485。之后的 ROS2 步骤完全相同。

--------------------------------------------------------------------------------
 6.1 准备串口
--------------------------------------------------------------------------------

 【虚拟】每个从站起一个假从站，它会打印自己的虚拟串口：

   cd ~/your_ws/src/auto_machine
   python3 -u fake_modbus_slave_closedloop.py

 双串口时再开一个终端跑一次，或改用后台方式：

   cd ~/your_ws/src/auto_machine
   python3 -u fake_modbus_slave_closedloop.py > /tmp/s0.log 2>&1 &
   python3 -u $PWD/fake_modbus_slave_closedloop.py > /tmp/s1.log 2>&1 &
   sleep 2 && grep -h NODE_PORT /tmp/s0.log /tmp/s1.log

 说明：一个实例提供一个虚拟串口，同一串口上同时模拟从站 0x01 与 0x02。

 【实机】

   ls -l /dev/ttyRS485*        # 确认软链接指向正确设备，见 2.2

--------------------------------------------------------------------------------
 6.2 启动节点
--------------------------------------------------------------------------------

 【虚拟 · 单串口】

   ros2 run auto_machine auto_machine_node --ros-args \
     -p serial_port:=/dev/pts/7 \
     -p auto_query_delay_ms:=200 -p auto_query_poll_interval_ms:=100

 【虚拟 · 双串口】

   ros2 run auto_machine auto_machine_node --ros-args \
     -p "mag_serial_ports:=['/dev/pts/7','/dev/pts/8']" \
     -p auto_query_delay_ms:=200 -p auto_query_poll_interval_ms:=100

 【实机】

   ros2 run auto_machine auto_machine_node --ros-args -p serial_port:=/dev/ttyRS485

 三种方式启动成功的标志相同：日志出现「串口已打开」和
 「串口数: N，执行器线程数: M」。

--------------------------------------------------------------------------------
 6.3 验证步骤
--------------------------------------------------------------------------------

 步骤 1  查询（确认两个从站地址不串）

   自动机（MAG06 准入状态）：
   ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 4, command: 262157, param_data: [0]}"

   对齐装置（主控状态）：
   ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 268435457, command: 16842756, param_data: [0]}"

   两者都 success=True、数值合理，说明 0x01 / 0x02 都能通信。

 步骤 2  单条闭环（确认状态能到位）

   ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 4, command: 262149, param_data: [0]}"
   ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 4, command: 262146, param_data: [0]}"

   缝制返回 ret_data=[0,3] 即为到位；返回 10008 表示通讯正常但状态没到目标值。

 步骤 3  跨从站互不干扰

   自动机执行较长闭环期间，查询对齐装置主控状态，应毫秒级返回，
   且不出现 10006 / 10009。

 步骤 4  故障上报（可选）

   ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 4, command: 4026531841, param_data: [1, 0]}"
   ros2 topic echo /auto_machine/fault

--------------------------------------------------------------------------------
 6.4 实机接线检查
--------------------------------------------------------------------------------

   1) 一条总线只能有一台 0x01 设备；XYZR 是 0x02，可与之共存
   2) A/B 不能接反；所有从站与 USB-485 必须共地
   3) 终端电阻只在总线两个物理末端各接 120Ω，中间设备不接
   4) 手拉手菊花链，避免星形分支
   5) 通讯参数固定 115200 / 8 / 奇校验 / 1 停止位

--------------------------------------------------------------------------------
 6.5 指令帧十六进制对照表
--------------------------------------------------------------------------------

 用调试界面或假从站日志核对时使用，末 2 字节为 CRC16（低字节在前）。

 用例                     命令号        期望帧
 -----------------------  ------------  ------------------------------------
 T1 开始工作              0x00010009    01 06 15 01 00 01 1D C6
 T1 关闭吸风              0x00010010    01 06 15 02 00 00 2C 06
 T1 状态查询              0x00010001    01 03 10 00 00 01 80 CA
 V6 舌板伸出              0x00020001    01 06 00 00 00 01 48 0A
 V6 机器状态查询          0x00020016    01 04 00 01 00 01 60 0A
 MAG04 开始吸风           0x00030001    01 06 00 64 00 01 09 D5
 MAG04 急停               0x00030003    01 06 00 64 00 03 88 14
 MAG04 查询吸风状态       0x0003000B    01 03 00 67 00 01 35 D5
 MAG04 查询准入状态       0x0003000D    01 03 00 66 00 01 64 15
 MAG06 开始吸风           0x00040001    01 06 10 64 00 01 0D 15
 XYZR 复位                0x01010001    02 06 00 00 00 01 48 39
 XYZR 主控状态查询        0x01010004    02 04 00 02 00 01 90 39

 帧结构（以 MAG04 开始吸风为例）：

   01       从站地址 0x01
   06       功能码：写单个保持寄存器
   00 64    寄存器地址 0x0064（D100 主控制命令）
   00 01    值 0x0001（开启吸风）
   09 D5    CRC16，低字节在前

 功能码：0x03 读保持 / 0x04 读输入 / 0x06 写单个保持
        （MAG/V6/T1 写后不等应答，XYZR 带应答）

================================================================================
 七、常见问题排查
================================================================================

--------------------------------------------------------------------------------
 7.1 错误码 → 原因 → 处理
--------------------------------------------------------------------------------

 10001 未知设备类型
   原因：dev_type 写错（例如用了 5 = A100 之外的保留值）
   处理：对照 1.4 的类型表

 10002 未知命令
   原因：command 号不存在；或使用了已删除的旧命令
        （典型：XYZR 的 16842757 / 16842758）
   处理：对照 5.7 速查表；确认固件版本与本手册一致

 10003 参数错误
   原因：MAG04/MAG06 没给 param_data[0]；索引超过串口数量；参数长度不符
   处理：显式传 param_data，并确认索引 < mag_serial_ports 元素个数

 10004 功能未实现
   原因：调用了预留设备/预留命令（如 A100）
   处理：无

 10005 内部错误
   原因：协议处理抛异常（一般是参数解析问题）
   处理：看节点日志里的 "处理命令异常"

 10006 通讯失败
   原因较多，按下面顺序排查：
     1. 串口没打开         → 节点启动日志有没有「串口已打开」
     2. 串口路径/索引错    → 对照 mag_serial_ports 与实际设备
     3. A/B 接反、没共地   → 用调试界面单独验证设备
     4. 波特率/校验不符    → 设备必须是 115200 8O1
     5. 地址冲突           → 一条总线上是不是挂了两台 0x01
     6. 偶发失败           → 同总线回显残留：自动机的 0x06 控制帧不回读应答，
                              残留回显可能被发往 0x02 的接收窗口读到，属已知现象

 10008 动作超时未到位
   原因：通讯正常，但状态寄存器在超时时间内没到目标值
   处理：
     · 先看返回的 ret_data 最后状态值，判断卡在哪一步
     · 核对协议里的到位枚举值是否与代码一致（改 closed_loop.cpp 一行即可）
     · 设备确实动作慢 → 调大 auto_query_timeout_ms
     · 状态寄存器地址/功能码写错（0x03 保持 与 0x04 输入 用反）

 10009 串口忙
   原因：同一串口上已有闭环命令在执行
   处理：
     · 正常行为，等前一条闭环结束后重试
     · 若频繁出现，说明上层不该并发下发闭环命令，应串行化业务
     · 查询/急停类命令不会返回 10009，可随时插入
