================================================================================
 auto_machine 节点 对外接口说明（闭环版 · 命令行手册）
 —— 每条都是可直接复制的 ros2 service call 命令，并写明返回值代表什么
================================================================================

 适用工程：auto_machine（ROS2，RS485 / Modbus RTU，115200 8O1）
 管控设备：T1、V6、MAG04、MAG06（从站地址 0x01）、XYZR（从站地址 0x02）
 多机能力：T1 / V6 / MAG04 / MAG06 / XYZR 全部支持。

--------------------------------------------------------------------------------
 〇、调用前准备
--------------------------------------------------------------------------------
 单机（所有设备共用 serial_port）：
    cd ~/auto_ws && source install/setup.bash
ros2 run auto_machine auto_machine_node --ros-args -p serial_port:=/dev/ttyUSB0 -p auto_query_timeout_ms:=60000

 多机（每台自动机一条串口，同一串口上同时挂 MAG 钉扣机 + XYZR 对齐装置）：
    ros2 run auto_machine auto_machine_node --ros-args -p "mag_serial_ports:=['/dev/ttyRS485_0', '/dev/ttyRS485_1']"
    · mag_serial_ports 顺序即设备索引：第 0 个 = 0 号机，第 1 个 = 1 号机。
    · 所有设备类型（T1/V6/MAG/XYZR）都用 param_data[0] 选择自动机（0/1...）。
    · T1/V6/XYZR 省略 param_data 时默认 0 号机（兼容单机旧调用）；
      MAG04/MAG06 必须显式提供索引。
    · 下面各章节示例统一写 param_data: [0]（0 号机）；1 号机把 [0] 改成 [1] 即可。
    · 同一串口上的自动机（从站 0x01）与 XYZR（从站 0x02）靠从站地址区分，
      共用一个 ModbusRtu 实例（独立总线锁），互不串线。

 然后在另一个终端执行下面的命令（每个新终端都要先）：
    cd ~/ros2_ws && source install/setup.bash

 统一服务名：/auto_machine/command
 服务类型：auto_machine/srv/AutoMachine
 请求字段：dev_type(设备类型) / command(命令号) / param_data(字节数组，多数为空)
 返回字段：success(布尔) / err_code(错误码) / ret_data(返回字节数组)

--------------------------------------------------------------------------------
 一、三类命令与返回怎么看（务必先读）
--------------------------------------------------------------------------------
  本工程的命令分三类：

  【闭环控制】（共 23 条，本文用〔闭环〕标注）
    节点下发动作后，会自动每隔一段时间查询对应状态寄存器，直到“动作到位”
    或超时才返回。你只发这一条命令，返回里就带最终状态值，不用再手动查询。
    · 到位返回：success=True  err_code=0     ret_data=[高字节,低字节]（最终状态值）
    · 超时返回：success=False err_code=10008  ret_data=[高字节,低字节]（最后一次状态）
    · 通讯异常：success=False err_code=10006  ret_data=[]（或最后状态）

  【仅下发控制】（协议里没有反馈位的动作，用〔仅下发〕标注）
    节点把指令写进设备就立即返回，设备“做没做完”协议无从查询。
    · 正常返回：success=True  err_code=0  ret_data=[]   （只代表指令已发出）
    这类包括：压框、暂停、下一步、取料、镭射灯、抚平、MAG 开始/关闭理布、急停、
    人工、吹气、压板等。

  【状态查询】（用〔查询〕标注）
    立即返回当前寄存器值，不做任何动作。
    · 正常返回：success=True  err_code=0  ret_data=[高字节,低字节]

  ret_data 数值换算（本工程状态值都小于 256，所以第 1 个字节恒为 0）：
    V = ret_data[0]*256 + ret_data[1]
    例：ret_data=[0,10] → V=10；ret_data=[0,3] → V=3；ret_data=[0,0] → V=0

  err_code 错误码表：
    0      成功
    10001  未知设备类型
    10002  未知命令
    10003  参数错误
    10004  功能未实现（A100 目前未实现，调用返回此码）
    10005  内部错误
    10006  通讯失败（串口打不开 / 设备无应答 / 应答校验错）
    10007  设备返回异常
    10008  动作超时未到位（闭环专用：规定时间内状态一直没到目标值）
    10009  串口忙：该串口已有闭环命令在执行，请稍后重试（见下方"并发行为"）

  闭环 3 个可调时间参数（启动节点时加，默认值如下，单位毫秒）：
    -p auto_query_delay_ms:=500          # 下发动作后，首次查询前等待
    -p auto_query_poll_interval_ms:=300  # 之后每隔多久查一次
    -p auto_query_timeout_ms:=30000      # 多久没到位就判超时（到位会立即返回，不傻等）
  例：整件缝纫较慢时把超时调到 60 秒：
    ros2 run auto_machine auto_machine_node --ros-args -p serial_port:=/dev/ttyUSB0 -p auto_query_timeout_ms:=60000

  设备类型 dev_type：T1=1  V6=2  MAG04=3  MAG06=4  XYZR=268435457(0x10000001)

--------------------------------------------------------------------------------
 并发行为（多串口并行版）
--------------------------------------------------------------------------------
  节点内部使用多线程执行器 + 可重入服务回调，因此：

  1) 不同串口互不阻塞
     串口0 正在等"缝制完成"（闭环，可能几秒到几十秒）时，串口1 的控制/查询命令
     仍会在毫秒级得到响应。走哪个串口由 param_data[0] 决定。

  2) 同一串口的闭环命令互斥（忙则拒，不排队）
     同一串口上已有闭环命令在执行时，再向该串口下发【闭环】控制命令，会立即返回
       success=False  err_code=10009  ret_data=提示文字
     不等待、不排队，由上层决定是否重试。
     注意：如果 UI 在按钮回调里同步调用服务，需要改成后台线程发请求，
           否则 UI 自己会被串口0 的闭环卡住，节点这边的并发就发挥不出来。

  3) 非闭环命令可插入执行
     状态查询、急停、压框、吹气等【仅下发】/【查询】类命令不占用串口，
     在闭环等待期间仍可正常下发并返回，不会被 10009 挡住。

  执行器线程数（可选参数，默认 0 = 自动）：
    -p executor_threads:=0     # 0=自动推导 max(4, 2×串口数)；串口很多时可手动调大

 二、T1（dev_type=1）
================================================================================

【T1-1】复位  〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65550, param_data: [0]}"
  到位返回：success=True err_code=0 ret_data=[0,1] 或 [0,3]
    V 为运行状态字，bit0(最低位)=1 表示回零/复位完成。
    V=1：复位完成；V=3：复位完成且本件缝纫也完成（V 为奇数即代表已复位）。
  超时：success=False err_code=10008，ret_data 为最后状态（bit0 仍为 0 说明没回零）。

【T1-2】开始工作（自动等到本件缝纫完成）〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65545, param_data: [0]}"
  到位返回：success=True err_code=0 ret_data=[0,2] 或 [0,3]
    bit1=1 表示本件缝纫完成。V=2：缝纫完成；V=3：复位+缝纫都完成。

【T1-3】打开吸风（等吸风确实开启）〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65548, param_data: [0]}"
  到位返回：success=True err_code=0 ret_data=[0,1]
    吸风状态 V 非 0 即“已开启”（正常为 1）。

【T1-4】关闭吸风（等吸风确实关闭）〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65552, param_data: [0]}"
  到位返回：success=True err_code=0 ret_data=[0,0]
    V=0 表示吸风已关闭。

【T1-5】压框下压  〔仅下发·无到位反馈〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65544, param_data: [0]}"
  返回：success=True err_code=0 ret_data=[]（仅代表指令已发出）

【T1-6】压框抬起  〔仅下发〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 65551, param_data: [0]}"
  返回：success=True err_code=0 ret_data=[]

 六、XYZR 对齐装置（dev_type=268435457，即 0x10000001，从站 0x02）
================================================================================
 多机说明：
   param_data[0] 为自动机索引（0/1...），与 mag_serial_ports 顺序一致；
   省略时默认 0 号（兼容单机旧调用）。下面示例以 0 号机 param_data:[0] 为例，
   1 号机把 [0] 改成 [1] 即可。
   同一串口上 MAG 钉扣机走从站 0x01，本对齐装置走从站 0x02，互不影响。

【XY-1】复位 / 主控回零（等回到就绪）〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 268435457, command: 16842753, param_data: [0]}"
  到位返回：success=True err_code=0 ret_data=[0,1]
    主控状态 V=1：准备就绪、可接收命令。
  过程中主控会经历 V=10（执行中/回零中），到位后变 V=1。

【XY-2】大身布料已放好，触发视觉检测+移料（两阶段闭环，等移料成功）〔闭环〕
  ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 268435457, command: 16842754, param_data: [0]}"
  节点内部自动做两阶段判断：先等“主控状态=11（执行完成）”，再读“移料结果”。
  到位返回：success=True err_code=0 ret_data=[0,1]
    最终 ret_data 是移料结果：V=1 移料成功、已移到位，可进行下一步缝纫；
    若移料失败 V=0，闭环判为未到位，继续等到超时后返回 success=False err_code=10008。

 七、故障主动上报（话题 + 开关）
================================================================================
  故障是节点后台线程主动轮询设备、发现异常后“推”上来的，走话题（不是服务返回）。

  订阅故障话题（有故障会自动打印，无需自己轮询）：
    ros2 topic echo /auto_machine/fault
  消息类型 auto_machine/msg/DeviceFault，主要字段：
    dev_type   哪台设备
    fault_code 故障码/状态值
    comm_fault true=通讯故障（设备掉线/串口读失败）；false=设备本身故障
  说明：开启监控后后台周期轮询（周期参数 fault_poll_interval_ms，默认 1000ms），
        状态发生变化（边沿）才推一次，开启瞬间会先发一条当前状态作为基准。
        T1/V6/MAG：故障码非 0 即报故障；XYZR：主控状态=100 才算故障。
        （XYZR 的 0x0003 故障代码可用【XY-查3】单独查询。）

  打开 / 关闭某设备的故障上报（全局命令，command 固定 4026531841=0xF0000001）：
    打开 T1 故障上报：
    ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 4026531841, param_data: [1]}"
    关闭 T1 故障上报：
    ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 4026531841, param_data: [0]}"
    （所有类型都支持 param_data:[enable, device_index] 指定自动机；
      T1/V6/XYZR 也可只给 1 字节 [enable]，默认 0 号机；MAG 必须 2 字节。）
     打开 0 号 T1 故障上报：
     ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 1, command: 4026531841, param_data: [1, 0]}"
     打开 0 号 MAG06 故障上报：
     ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 4, command: 4026531841, param_data: [1, 0]}"
     打开 1 号 XYZR 故障上报：
     ros2 service call /auto_machine/command auto_machine/srv/AutoMachine "{dev_type: 268435457, command: 4026531841, param_data: [1, 1]}"
    返回：success=True err_code=0 ret_data=[] 表示开关设置成功。
